पहली बार — तीन चीज़ें
─────────────────────

  1. GitHub CLI लगाओ और login करो

         sudo apt install gh
         gh auth login

     "GitHub.com" चुनना, फिर "HTTPS", फिर browser से login.

  2. git को अपनी पहचान बताओ (अगर पहले नहीं बताई)

         git config --global user.name "Kanak Prabhakar"
         git config --global user.email "तुम्हारा@email"

     Email वही डालना जो GitHub खाते में है, वरना commits तुम्हारे
     नाम से नहीं दिखेंगे.

  3. pariyojana.tsv में रास्ते ठीक करो

     मैंने जो रास्ते लिखे हैं वो अंदाज़े हैं. अपनी मशीन के असली
     रास्ते डालो. जो project अब मौजूद नहीं, उसकी लाइन हटा दो.

     ध्यान: खानों के बीच TAB होना ज़रूरी है, space नहीं.


फिर — इसी क्रम में

      ./bhandar.sh dekho

  क्या-क्या होगा, कुछ बदले बिना. रास्ते सही हैं या नहीं, यहीं दिख जाएगा.

      ./bhandar.sh jaancho

  हर project में गुप्त चीज़ें ढूँढता है. जिन पर "रुको" आए, उन्हें

  असल में repo बनाता है और push करता है. शुरू करने से पहले बताता है
  कि कितने public बनेंगे और पूछता है — "haan" लिखो तभी आगे बढ़ता है.

      ./bhandar.sh haal

  कौन सा project कहाँ तक चढ़ा.


राज़ जाँच के बारे में — यह छोड़ना मत
──────────────────────────────────────

  GitHub पर एक बार जो चला गया, वो हमेशा के लिए चला गया.

  Commit हटाने से भी नहीं जाता — GitHub पुराने commits अपने पास रख
  लेता है और वो URL से खुलते रहते हैं. Repo private कर दो, तब भी जो
  पहले copy हो चुका वो वापस नहीं आता.

  और bots GitHub को लगातार खंगालते हैं. Public repo में गई API key
  मिनटों में इस्तेमाल हो जाती है, घंटों में नहीं.

  इसीलिए script public project को तब तक push नहीं करता जब तक जाँच
  पास न हो. इसमें कोई ढील नहीं है, और नहीं होनी चाहिए.

  किसी एक project को अलग से जाँचना हो:

      python3 aujaar/raaz_jaancho.py ~/Desktop/कोई-project


  जाँच दो जगह देखती है — यह समझ लेना ज़रूरी है
  ─────────────────────────────────────────────

  push वो चीज़ भेजता है जो git के पास है, वो नहीं जो folder में पड़ी है.
  ये दोनों एक नहीं हैं.

  १. अभी की files — पर सिर्फ़ वो जो git सचमुच भेजेगा.

     .gitignore की हुई .env कभी push नहीं होती, इसलिए अब उस पर जाँच
     नहीं रुकती. पहले रुकती थी — और वो ग़लत था: तुम सब कुछ सही करके
     भी हमेशा "रुको" देखते रहते, और कुछ कर भी नहीं सकते थे.

     पूरा folder देखना हो तो:  --sab लगा दो.

  २. पुराना इतिहास — और यही सबसे ज़रूरी है.

     अगर key एक बार commit हुई और अगले commit में file हटा दी गई, तो
     folder साफ़ दिखता है — पर key इतिहास में बैठी रहती है और push के
     साथ GitHub पर चली जाती है.

     पहले यह जाँच नहीं थी. ऐसा project "साफ़ है, public किया जा सकता
     है" दिखाता था — जबकि key जाने ही वाली थी. अब पकड़ी जाती है.

     इतिहास वाली key के लिए file हटाना काफ़ी नहीं. या तो project
     private रखो, या इतिहास नए सिरे से बनाओ (rm -rf .git && git init)
     — और वो सोचकर करना, पुराने commits चले जाएँगे.


  झूठा अलार्म हो तो
  ──────────────────

  कभी-कभी जाँच नक़ली key पर भी रुक जाती है — जैसे उदाहरण में लिखी
  हुई key, या कोई 16 अंकों की आम संख्या.

  उस लाइन का टुकड़ा project में .raazignore नाम की file में लिख दो,
  एक लाइन में एक. जिस लाइन में वो टुकड़ा मिलेगा, वो छोड़ दी जाएगी.

  सोचकर लिखना. यह जाँच को कमज़ोर करने का रास्ता है, और उसी काम के
  लिए है — इसलिए सिर्फ़ तब जब तुम्हें पक्का पता हो कि वो नक़ली है.


public या private — कैसे तय करें
──────────────────────────────────

  public तब जब — कोई और उससे सीख सके, या तुम उसे दिखाना चाहते हो
                  (internship, admission, GitHub की शक्ल)

  private तब जब — किसी और का नाम/data उसमें है, या कुछ गुप्त हो
                  सकता है, या वो अभी अधूरा है

  शक हो तो private. Public बाद में एक क्लिक में हो जाता है.
  उल्टा नहीं होता — जो एक बार public हो गया, वो हो गया.


दो copy वाली बात
─────────────────

  तुमने पूछा था कि एक copy laptop पर रहे और एक GitHub पर.

  git यही करता है, अपने आप. `git push` के बाद दोनों जगह पूरा इतिहास
  रहता है. अलग से backup बनाने की ज़रूरत नहीं.

  रोज़ के काम में बस इतना:

      git add -A
      git commit -m "आज क्या किया"
      git push

  Claude Code को कहो तो वो हर बड़े बदलाव के बाद यह ख़ुद कर देगा.


भंडार ख़ुद ठीक चल रहा है या नहीं
──────────────────────────────────

      ./parakh.sh

  यह भंडार की अपनी जाँच है. असली folder बनते हैं, असली git repo बनते
  हैं, और असली script चलती है — कोई test सिर्फ़ string मिलाकर पास नहीं
  होता.

  script में कुछ बदलो तो यह चलाकर देख लेना.

  जो इसमें नहीं जाँचा जाता वो सबसे नीचे लिखा है: 'karo' का असली
  हिस्सा (gh repo create, git push). उसके लिए GitHub पर सचमुच repo
  बनाना पड़ता, इसलिए वो हाथ से जाँचना होगा.
